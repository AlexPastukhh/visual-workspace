# visual-workspace

Приватный репозиторий визуальных проектов и результатов. Создание, исправление,
визуальное QA и интеграция в игру должны оставаться отдельными этапами от
**публикации результата для владельца**.

- [UC-VIS-009 — Обратная связь, версии и публикация медиа в GitHub](docs/use-cases/media-github-review.md#uc-vis-009)
- [Backlog — публикация нескольких версий в один Issue, оригиналы 3D/видео](docs/BACKLOG-IMPROVEMENTS.md)

**Сегодня:** Fortis умеет размещать 1–5 PNG в **новом приватном GitHub Issue**
через owner-ASK. Следующий `run_id` создаёт **другой Issue**; добавление
версий в исходный Issue пока не реализовано. Репозиторий Git — источник
истории сохранённых исходников; GitHub Issue — витрина для просмотра, а
Docker QA-кэш не является вечным архивом.

Для новой задачи ИИ выбирает сценарий, создаёт исходники в **своём** task
worktree, проверяет результат и показывает согласованное PNG-превью по
`UC-VIS-009`. Для самой игры после PR/CI/owner merge и Mirror Pull Windows
`main` пользователь проверяет проект в Godot на Windows. GitHub Issue —
витрина обратной связи, не замена редактируемым исходникам.

Blender/Godot и их библиотеки устанавливаются **отдельно от Git**, в
игнорируемой `.local-tools` на Docker primary. В task worktree использовать
`./tools/link-shared-tools.sh`, не коммитить бинарники сред. Манифесты,
QA-кэш и временные рендеры не являются автоматически сохранённой Git-версией.

**UC-VIS-008 — практические проверки новых чатов:** [готовые промпты и тестовые
наборы](practical-tests/README.md) содержат письменные задания для создания
2D/3D, проверки анимаций, градации сложности и протокол измерения времени.
Один новый чат получает один тестовый промпт; при просмотре обычно это 2–3
анимации, при создании — один заказ. Выводы оцениваются отдельно после ответа,
по эталонам; публичные GitHub Issues для тестовых материалов **не создаются
без отдельного задания владельца**. Вход для тестового чата — принятый
`/workspace/repo/Repos/visual-workspace/README.md`, не старый task worktree.
Этот набор не заменяет [UC-VIS-009](docs/use-cases/media-github-review.md#uc-vis-009):
при настоящем показе результата владельцу действуют именно его правила.
