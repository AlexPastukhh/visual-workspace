АКТУАЛЬНОЕ ОГРАНИЧЕНИЕ ИНСТРУМЕНТОВ: это Visual QA через Fortis Repo и готовые исходные кадры Visual Workspace. НЕ используй image_gen, генераторы AI-картинок, текст-в-изображение или синтетические кадры. НЕ меняй исходные материалы; только читай реальные PNG и делай доказательную оценку. В этом режиме GitHub публикации запрещены.

Работай через подключение Fortis Repo.

**Сначала прочитай README Visual Workspace:**

`/workspace/repo/Repos/visual-workspace/README.md`

Выполни описанный там bootstrap, прочитай необходимую документацию и следуй установленным юзкейсам, workflow и правилам Visual QA.

**Твоя задача — самостоятельно проверить одну 2D-анимацию.**

Анимация находится здесь:

`/workspace/repo/Repos/visual-workspace/practical-tests/visual/cases/clip-k7/`

Сначала прочитай её письменное задание (`brief.md`) и описание кадров (`capture.json`).

Затем просмотри анимацию по правилам Visual Workspace. Используй реальные изображения: контактный лист и оригинальные полноразмерные PNG в хронологическом порядке. При необходимости изучай соседние кадры, чтобы проверить непрерывность движения.

Определи:

1. Соответствует ли анимация письменному заданию?
2. Есть ли ошибки или визуальные недостатки?
3. Какие конкретно кадры и моменты времени подтверждают твои выводы?
4. Какие проблемы ты можешь подтвердить, а какие остаются предположениями?

Не предполагай заранее, что в примере обязательно присутствует дефект.

Не читай `practical-tests/_evaluator/`, старые отчёты или результаты других проверок.

Не публикуй тестовые изображения в GitHub, не вызывай `publish_visual_review` и не создавай owner ASK на публикацию. Не изменяй исходники и тестовые материалы.

Создай уникальную папку внутри `/workspace/repo/Workfiles/visual-workspace-practical-tests/runs/` и сохрани туда отчёт `review.md`.

В итоговом ответе сообщи результат проверки, какие кадры действительно просмотрел, и точный путь к отчёту.

Выполни задание самостоятельно, используя существующий workflow.
