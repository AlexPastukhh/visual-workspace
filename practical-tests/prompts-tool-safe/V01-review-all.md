АКТУАЛЬНОЕ ОГРАНИЧЕНИЕ ИНСТРУМЕНТОВ: это Visual QA через Fortis Repo и готовые исходные кадры Visual Workspace. НЕ используй image_gen, генераторы AI-картинок, текст-в-изображение или синтетические кадры. НЕ меняй исходные материалы; только читай реальные PNG и делай доказательную оценку. В этом режиме GitHub публикации запрещены.

# V01 — Слепая проверка пяти 2D/3D-анимаций

Работай через подключение Fortis Repo. Сначала прочитай /workspace/repo/README.md и обязательные для нового чата правила Fortis, затем `/workspace/repo/Repos/visual-workspace/README.md` и `/workspace/repo/Repos/visual-workspace/AGENTS.md`. Выполни предусмотренный там bootstrap, выбери применимые юзкейсы, прочитай WORKFLOW.md и документацию инструментов/QA, которая нужна именно для этого задания.

Все источники и подготовленные примеры в visual-workspace используй только на чтение. Создай собственную новую папку с уникальным именем внутри /workspace/repo/Workfiles/visual-workspace-practical-tests/runs/ и сохраняй все свои результаты только туда. Не меняй репозиторий, не публикуй изменения, не очищай чужие файлы.

Твоя задача — самостоятельно оценить пять анимаций в каталоге /workspace/repo/Repos/visual-workspace/practical-tests/visual/cases/: clip-k7, clip-m4, clip-r2, clip-t9 и clip-w8. У каждого примера прочитай brief.md и capture.json, затем **действительно просмотри** контактный лист и реальные PNG-кадры по стратегии из Visual Workspace. Некоторые примеры могут иметь существенные дефекты, другие могут быть корректны; не предполагай результат заранее. Просмотри достаточную временную последовательность, чтобы проверить кратковременные сбои, переходы, циклы и приземление.

Составь отдельное заключение для каждого клипа: соответствует ли он письменному brief, что конкретно ты наблюдал, есть ли дефект, какие кадры/время это подтверждают, насколько ты уверен. Не выдумывай недостатки. Не читай эталонные ответы, старые ревью или результаты других тестовых чатов. Не исправляй анимации. Сохрани пять отдельных отчётов и общий краткий итог в созданную папку Workfiles, сообщи её путь и ограничения проверки.

Это только испытание визуальной проверки. Не публикуй материалы в GitHub,
не вызывай `publish_visual_review` и не создавай owner ASK без отдельного
поручения владельца.
