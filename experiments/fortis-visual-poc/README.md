# Fortis Repo — local visual feedback PoC (2026-10-27)

This is an isolated smoke test. It does **not** modify any Godot game or production project.

## Tested paths
- 2D pixel drawing: editable `sprite.svg`, real raster output `sprite.png`.
- 2D vector drawing: editable `vector.svg`, real raster output `vector.png`.
- 3D mesh: actual `house.obj` plus material definitions in `house.mtl`.
- 3D inspection image: `house_preview.png`, generated by projecting the mesh's polygon faces (not a Blender/Godot render).
- Visual loop: an occlusion defect was noticed in the first preview, the painter order was corrected, and a new PNG was read back through Fortis Repo.

## Reproduce
```bash
cd /workspace/repo/Workfiles/fortis-visual-poc
python3 generate.py
node - <<'JS'
const fs=require('node:fs');
const {Resvg}=require('@resvg/resvg-js');
for (const n of ['sprite','vector','house_preview'])
  fs.writeFileSync(n+'.png',new Resvg(fs.readFileSync(n+'.svg','utf8')).render().asPng());
JS
```

## Scope and next tests
- Confirmed: Fortis Repo terminal -> generated editable image/mesh -> PNG -> Fortis Repo image reader -> ChatGPT visual inspection.
- Not yet confirmed: Blender rendering, Godot local graphical capture, real Windows GUI editing, GPU acceleration, 3D render/rigging fidelity.
- The custom OBJ test is for visualization only, not a guaranteed watertight 3D-printable solid.
- The pinned `@resvg/resvg-js` package is installed only within this test folder.
